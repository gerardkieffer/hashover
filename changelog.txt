HashOver 2.0.0 (unreleased)
--------------------------------------------------------------------------------
A complete rewrite; not compatible with HashOver 1.x installations, embed
codes or comment files. See README.md for installation and SECURITY.md for
the security design.

* PHP 8.4+, Composer, PSR-4 classes, SQLite storage, Twig templates.
* Only the "public" directory is served.
* One renderer: comments work without JavaScript; hashover.js enhances them
  and is compatible with a strict Content-Security-Policy.
* Accessibility: WCAG 2.1 AA target (labels, errors, focus, live regions,
  keyboard, reflow).
* Security: rate limiting, CSRF tokens, signed admin sessions with logout,
  encrypted e-mails, sanitizer based on the HTML5 parser, bot protection.
* Privacy: Gravatar, IP storage and stopforumspam are opt-in; IP addresses
  are forgotten after a retention period; likes use a keyed hash.
* Comment counts, RSS feeds, sorting, popular comments, notifications,
  editing and deleting kept; French, German, Spanish and Japanese fully
  translated.
* Per-page interface language ("language" parameter, Embed::thread()
  argument or data-hashover-language), so translations of a page can share
  one thread.
* The comment form's heading shows the title of the page being viewed; the
  title stored with a thread's first comment is the fallback (and is still
  what e-mails and the RSS feed use).
* Removed: Identi.ca/Twitter name links, user-agent sniffing, "count_link"
  script (use data-hashover-count), HTML-file templates (use Twig).
* bin/hashover: setup, check, hash-password, purge-ips.
* Optional Akismet spam filter ("akismet_key"): checks new and edited
  comments and rejects spam; accepts comments when Akismet can't answer.
* Optional Cloudflare Turnstile bot check ("turnstile_site_key",
  "turnstile_secret_key"): shown in the comment form; liking, replying,
  posting and saving are grayed out, with a note, until it is completed. A
  completed check gives a signed pass cookie bound to the visitor's address
  for "turnstile_pass_minutes" (60 by default); the server refuses posts,
  edits and likes without it. Needs hashover.js, and the host page's CSP
  must allow challenges.cloudflare.com.
* "bin/hashover check" asks Akismet and Turnstile whether they accept the
  configured keys.


Changes for PHP 8.4 and security hardening 2026-10-04
--------------------------------------------------------------------------------
* Runs on PHP 8.1+ (tested with 8.4); fixed the fatal error in "like.php" and
  PHP 8 comparison bugs, modernized the code (strict types, typed functions).
* Fixed many cross-site scripting issues: all output is now escaped, and data
  in JavaScript mode is emitted as JSON.
* Fixed path traversal in comment editing, deleting, replying and liking.
* Passwords are hashed with password_hash(); old MD5 hashes keep working and
  are upgraded the next time they are used.
* E-mail addresses are encrypted with libsodium; old ones are still readable
  and are re-encrypted when the comment is edited.
* Passwords are no longer stored in cookies. Login and admin cookies are
  HMAC tokens; all cookies are HttpOnly and SameSite=Lax (Secure on HTTPS).
* Cross-site form submissions and likes are rejected; likes are POST only.
* Nobody but the administrator may use the administrator's nickname.
* Websites must be http(s) URLs; e-mail addresses must be valid.
* Notification e-mails are always sent from $noreply_email.
* Comment files are created atomically and can't overwrite each other.
* Comment directories are only created when a comment is posted.
* Comments are limited to $max_comment characters (settings.php).
* stopforumspam.com is queried over HTTPS, only when posting.
* Added .htaccess files denying access to "pages", "scripts" and data files.

* Upgrade notes: keep your "secrets.php" (especially $encryption_key). Visitors
  need to log in again. Add the new $max_comment setting to a preserved
  "settings.php". Thread directory names now only keep the characters
  A-Z a-z 0-9 % ~ @ , ; ( ) and "-"; URLs containing other characters may map
  to a new directory.

Changes by Jacob Barkdull 2014-03-25
--------------------------------------------------------------------------------
Official mark of version 1.0!

* All necessary files (source code and images) are now available via:

	ZIP archive: http://tildehash.com/hashover.zip
	GitHub: https://github.com/jacobwb/hashover

* Please commit your changes to GitHub and make sure to read the GitHub page
  carefully for coding guidelines and copyright information.

* Added new comment sorting feature with five sorting methods:

	In Order
	In Reverse Order
	By Commenter
	By Date (newest first)
	By Likes

* Locale support, only three languages supported right now: English, Spanish,
  and Japanese. More languages will be added, those three are simply the ones
  of which I have at least some knowledge. More, further, and better
  translations are welcome and appreciated.

* Individual IP addresses can now be blocked by adding them one per line to a
  file called "blocklist.txt" in the "hashover" directory. In addition to that,
  if the variable "$spam_IP_check" is set to 'php', 'javascript', or 'both' a
  visitor's IP address will be checked against stopforumspam.com's database.

* E-mail notifications per comment can now be disabled by unchecking the
  "Subscribe" checkbox in the "Edit Comment" form.

* Added administration support for deletion and editing of all comments. Set
  the "$admin_nickname" and "$admin_password" variables in the "secrets.php"
  file to appropriate values. Read the "IMPORTANT" notice carefully.

* Many, many major changes to accommodate said and following changes.
* The script has been split into multiple files in "hashover/scripts" directory.
* Removed all JavaScript from PHP-mode (except code for liking a comment).
* "Reply" and "Edit" forms are now part of the dynamically generated HTML.

* Added "Login" button. It simply sets the necessary cookies that allow users
  to edit, delete, and (un)subscribe to/from email notifications.

* Removed Jeremiah Stoddard as secondary copyright holder since his
  contributions are no longer present in the current codebase, or rather, the
  codebase has changed enough that he would have no legal precedent to claim
  ownership any longer. Not that I expect any trouble.

* Fixed bug that caused a comment to become uneditable after you post another
  comment with a different e-mail address as the last. Cause: conditions to
  display the "Edit" link were based on a name+e-mail+password scheme.

* Renamed "comments.php" to "hashover.php".
* Renamed "comments" directory to "hashover".
* Moved code for automatic links and embedded images out of "write_comments.php"
* Avatar icons that fail to load now get same style as when icons are disabled.
* Temporarily disabled Identi.ca avatar support (see avatars.php) for why.
* Added "reply" to "cmtdiv" CSS class elements to control how replies look.
* Added "nickname" and "likes" to RSS feeds for use as API.
* Removed name and horizontal row from RSS descriptions.
* Now checks PHP version, fails if not 5.3.3 or higher.
* Improved how comment deletion notices are handled.
* Changed format of changelog.
* Minor CSS changes.
* Minor bug fixes.
