## New suggestions found while building HashOver 2

Ordered roughly by value. None of them were implemented, as they need a decision or add features.

### Worth doing soon

1. **Client IP behind proxies.** Behind a reverse proxy or CDN, every visitor shares the proxy's address, so they share rate limits and likes. Add a `trusted_proxies` setting and read `X-Forwarded-For` only from those addresses.
2. **Release automation.** Add a GitHub Actions workflow that, on a version tag, runs `composer install --no-dev`, and attaches a zip with `vendor/` to the release, for hosts without Composer. `.gitattributes` already excludes development files from archives.
3. **Browser tests in CI.** The JavaScript and accessibility checks were done by hand in a browser (keyboard flow, focus, axe-core, 320 px reflow). Playwright with `@axe-core/playwright` would keep them from regressing.
4. **Heading level option.** The thread uses an `<h2>` heading and `<h3>`/`<h4>` below it. Pages whose structure needs another level must override templates; a `heading_level` setting would be simpler.
5. **CIDR ranges in `blocked_ips`**, e.g. `203.0.113.0/24`, and IPv6 prefixes.

### Features to consider (out of scope so far)

6. **Moderation:** an optional approval queue and a page listing recent comments for the administrator.
7. **SMTP sending** (e.g. with `symfony/mailer`), as `mail()` is often unavailable or ends up in spam folders.
8. **Edit links by e-mail** for commenters who forgot their password.
9. **Data export and deletion** commands (GDPR requests), e.g. `bin/hashover export --email=…`.
10. ~~**Akismet** or a similar spam service, opt-in.~~ Done, along with Cloudflare Turnstile. With a moderation queue (6), Akismet's spam could be held for review instead of rejected, and reported back to Akismet as spam or not.

### Smaller ideas

11. Cache-busting file names (or a `?v=` parameter) for `hashover.js` and `hashover.css` when upgrading.
12. A `bin/hashover` command to clear the Twig cache after editing templates (it reloads automatically today, at a small cost).
13. More languages: contributors can add a file to `locales/` and its code to `Config::LANGUAGES` (the test suite checks that every message and placeholder is translated).
14. Use `intl`'s `MessageFormatter` for plural rules if languages with complex plurals (Polish, Arabic…) are added.
